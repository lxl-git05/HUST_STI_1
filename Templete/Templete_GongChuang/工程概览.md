# Templete_GongChuang 工程概览

> 文档定位：供后续 Agent 在修改代码前快速建立工程心智模型。内容更新至 2026-09-19；若 `.ioc`、模式枚举或硬件接线发生变化，应同步更新本文。
>
> **协作硬性约束：张大头 Emm_V5 步进电机的所有测试程序只能写在 `Mode_2.c`（必要声明放 `Mode_2.h`），不得写入 `main.c`、`Mode_G.c`、驱动层或其他 Mode。**

## 1. 一句话介绍

这是一个面向工创/机器人控制场景的 **STM32F407ZGT6 裸机固件模板**。工程以 STM32CubeMX/HAL 完成芯片和外设初始化，在其上封装 GPIO、PWM、编码器、串口、OLED、按键、IMU、AT24C02 参数持久化等通用能力，并用“全局模式 + 6 个业务模式”的状态机组织实验和后续业务逻辑。

当前仓库更接近“可持续扩展的控制板基础工程”，不是已经完成的单一产品：基础设施较完整，Mode 1 已用于离线调参，Mode 2 用于 IMU 实验输出，Mode 3～6 主要仍是业务占位模板。

### 3.1 生成代码与自有代码边界

- `Core/` 由 CubeMX 管理。必须把手写内容放在 `USER CODE BEGIN/END` 区域，否则重新生成代码可能覆盖修改。
- `Drivers/` 是 ST 上游依赖。它体量最大，但不是本项目业务逻辑；除非定位 HAL/CMSIS 本身的问题，否则不要修改。
- `MDK-ARM/Template/` 是构建输出目录；不要把产物当源代码修改。
- `Top/`、`Mode/`、`MySystem/`、`Hardware/`、`Function/`、`IMU/`、`AT/`、`Software/`、`Tools/` 是主要自定义代码区。
- `AllHeader.h` 是便捷的聚合头文件，耦合度较高。新增模块后若希望全局可见，需要同时考虑 Keil 分组、Include Path 和该聚合头文件。

## 4. 启动与核心调用链

```text
复位/启动文件
  → main()
    → HAL_Init()
    → SystemClock_Config()                # 168 MHz
    → MX_GPIO/DMA/ADC/I2C/TIM/UART_Init() # CubeMX 外设初始化
    → Mymain()
      → Mode_G_Setup()
        → Initial_ALL()
          → OLED_Init / RGB_Init / IMU_Mahony_Init
          → Serial_Init / Encoder_Init / Param_AT24C02_Init
          → Flash_Mode_Init / Timer_Counter_Init
        → Initial_Timer()                 # 最后启动周期中断
        → 从 EEPROM 恢复上次模式
      → 永久前台循环
        → OLED_Clear()
        → Mode_G_Loop()                   # 全局按键、模式请求等
        → 当前 Mode 的 Loop() 或 Exit/Setup 切换
        → 模式变化时写 AT24C02
        → OLED_Update()
```

`main.c` 自己的 `while (1)` 实际不会运行，因为 `Mymain()` 内部已经进入永久循环。后续业务入口应放在 Mode 层或定时回调中，而不是继续往 CubeMX `main()` 的循环里堆代码。

## 5. 运行时模型

工程把工作分成“前台非实时逻辑”和“周期实时逻辑”两部分：

| 执行上下文 | 来源 | 当前职责 | 编写约束 |
|---|---|---|---|
| 前台循环 | `Mymain()` | OLED 刷新、全局模式处理、各 Mode 的 `Loop()`、模式切换和持久化 | 可做状态机和显示；仍应避免长时间阻塞 |
| 1 ms 中断 | TIM6 → `Timer_1ms_Callback()` | 按键扫描、LED 闪烁节拍 | 必须短小，不做打印、EEPROM 写入或长延时 |
| 10 ms 中断 | TIM10 → `Timer_10ms_Callback()` | 预留给较快控制环（注释称球平衡） | 当前为空；适合快速采样/控制，不适合阻塞调用 |
| 20 ms 中断 | TIM7 → `Timer_20ms_Callback()` | Mahony IMU 更新，并按当前模式分发 `Mode_N_Tick()` | Mode 2 当前每 20 ms 通过串口输出一次 yaw |
| UART/DMA 中断 | USART/UART + DMA | Receive-to-idle 收包，识别 ABC/HEX 协议并重启 DMA | 回调操作共享缓冲区，前台读取时要考虑并发一致性 |
| EXTI 中断 | PF3/PF7 | EC11 旋转编码器增减计数 | 前台通过 `Encoder_Get()` 读取并清零 |
| PWM 更新中断 | TIM9/TIM12 | 为步进电机脉冲计数预留弱回调 | 仅在显式启用相应定时器更新中断后生效 |

周期定时器由 `MyTimer.c` 提供弱回调、由 `Mode_G.c` 给出实际实现。这种做法让定时器底层与业务分发解耦，但同名回调只能有一个强定义。

## 6. 模式状态机

核心状态是 `curr_mode`（正在运行）和 `next_mode`（请求切换到）。每个模式遵循统一生命周期：

```text
Mode_N_Setup() → Mode_N_Loop() 重复执行 → Mode_N_Exit()
                       ↑
              Mode_N_Tick() 由 20 ms 中断分发
```

| 模式 | 当前用途/成熟度 |
|---|---|
| `Mode_G` | 全局层：初始化、KEY0 切换模式、1/10/20 ms 定时任务、状态转换 |
| `Mode_1` | 已实现主要骨架：OLED 离线参数编辑，并与 AT24C02 联动；当前注册 `curr_mode` 和一个 IMU 陀螺仪零偏，其他零偏注册代码被注释 |
| `Mode_2` | 实验模式：OLED 显示模式名，每 20 ms 输出绝对偏航角 |
| `Mode_3`～`Mode_6` | 基本为空，仅保留 Setup/Loop/Tick/Exit 接口和 OLED 标题 |

切换流程会先调用旧模式 `Exit()`，再调用新模式 `Setup()`，随后更新 `curr_mode`。非 `Mode_Null` 模式变化时会把模式写入 EEPROM，以便下次上电恢复。

`Mode_2` 是本工程唯一允许编写张大头步进电机测试程序的位置。当前 Mode 2 的 USART1 IMU 周期打印会与 Emm_V5 的 USART1 TX DMA 发送冲突；后续写电机测试时，只在 Mode 2 内停用或替换该打印，不要把测试逻辑转移到全局层。

新增模式时至少要同步修改：`Mode_G.h` 枚举、`Mymain.c` 的 Loop/Exit/Setup 三处分发、`Mode_G.c` 的 Tick 分发、`AllHeader.h`、Keil 工程分组。枚举值和 EEPROM 中保存的模式值直接相关，不应随意重排已有值。

## 7. 主要模块说明

### 7.1 `Top/`：应用总装层

- `Mymain.c` 是真正的应用入口和前台调度器。
- `AllHeader.c` 集中进行自定义模块初始化，并强制把周期定时器放到最后启动，避免中断提前访问尚未初始化的数据。
- `AllHeader.h` 聚合几乎全部业务头文件，方便 Mode 开发，但也会放大循环依赖和编译耦合。

### 7.2 `MySystem/`：HAL 适配与板级实例

- `MyGPIO`：将 HAL 端口/引脚封装成实例，统一读写。
- `MyPWM`：启动 PWM、比较值限幅、修改 ARR、读取时钟并启用更新中断。
- `MyEncoder`：基于 TIM2/TIM3 编码器模式读取增量和累计计数。
- `MyTimer`：启动 TIM6/TIM7/TIM10，并把 HAL 周期回调转发到弱业务回调。
- `MySystem.c`：把逻辑设备绑定到实际 GPIO、TIM 和通道，是“硬件接线到软件对象”的集中映射点。

### 7.3 `Hardware/` 与 `Function/`：人机交互和通信

- OLED：软件 GPIO 时序驱动，`OLED.c` 和字模数据体量较大；前台每轮先清屏、最后整屏更新。
- Key：1 ms 扫描，识别按下、释放、单击、双击、长按和连发事件。
- EC11：两个外部中断通道更新计数，供参数编辑器等模块消费。
- RGB/LED：GPIO 指示；`LED_Flash` 在 1 ms Tick 中生成常亮、慢闪、快闪、瞬闪状态。
- 串口：USART1、USART2、UART4 被封装为 `Serial1/2/4`，均为 115200 8N1，DMA Receive-to-idle 收包。USART3 虽已由 CubeMX 配置，但当前未封装成 `Serial3`。
- 协议：支持字符串帧 `@DATA$#`（ABC）和二进制帧 `FF AA LEN [高字节 低字节 XOR校验]... 55 FE`（HEX）。
- 陶晶驰屏：默认走 `Serial4`，支持按键、滑块/参数、命令匹配和最多 4 通道波形发送；配套 HMI 文件在 `YJC_LCD/`。
- 张大头闭环步进电机：`Emm_V5.c/.h` 通过 USART1 DMA 发送 X42/Y42 命令，分为单电机立即发送和 Y42 多电机 MMCL 聚合两套接口。完整分类与风险见根目录 `张大头步进电机代码分类.md`。

### 7.4 `IMU/`：双传感器统一姿态接口

同时提供 MPU6050 与 ICM42688 的寄存器驱动、角度计算和 Mahony 融合实现。两者共用 I2C1 和地址 `0x68`，物理上只能二选一；当前 `IMU.h` 定义了 `IMU_USE_MPU6050`，因此编译期选择 MPU6050。

上层只依赖 `IMU_Mahony_*` 和 `IMU_Yaw_*` 宏映射，因此切换芯片主要改 `IMU.h`。统一层还提供偏航到位判断、Z 轴角速度绝对值、以及把机体系加速度转换到世界系水平分量的接口。20 ms Tick 负责姿态更新，即名义更新频率为 50 Hz。

### 7.5 `AT/`：参数持久化与离线调参

- `bsp_at24c02`：当前 `AT24C02_USE_SW_I2C=1`，使用 PA4/PA5 软件 I2C；也保留切到硬件 I2C2 的实现。
- `at24c02_manager`：最多注册 30 个 `int8/int16/int32/float` 参数，按注册顺序连续分配 EEPROM 地址，通过变量指针读写。
- `Param_AT24C02`：把 Mode 1 中的业务参数表注册到管理器，并提供初始化、单项/批量读写、整片擦除接口。
- `ParamEdit`：OLED + 按键 + EC11 的参数编辑状态机，最多显示/编辑 30 个参数，并可立即写 EEPROM。

关键约束：EEPROM 没有存储 schema 版本、参数 ID 或 CRC，地址完全由 `s_AT_Params[]` 的顺序和类型大小决定。向中间插入、删除或改类型会让旧数据与新变量错位；变更参数表后应按 `AT24调参注意事项.md` 处理擦除/迁移。读取逻辑把“全部字节为 `0xFF`”视为未初始化，因此当前协议无法可靠保存某些字节表示恰好全为 `0xFF` 的合法值。

### 7.6 `Software/` 与 `Tools/`

- `MyPID`：位置式 PID，含输出/积分限幅、微分先行系数、微分低通滤波和可选特殊处理回调。
- `Queue`：固定 50 项的环形队列；每项由一个任务类型和最多 4 个 `float` 参数组成。当前工程尚未看到完整任务执行器接入。
- `Timer_Counter`：基于定时器计数做代码段耗时和调用周期测量。
- `LED_Flash`：把系统状态映射为 LED 闪烁模式。

## 8. 外设与关键引脚概览

下表只列主要资源；修改接线前应同时核对 `Template.ioc`、`Core/Inc/main.h` 和根目录 `引脚分配表.md`。

| 功能 | 外设/引脚 | 用途 |
|---|---|---|
| IMU 总线 | I2C1，PB6/PB7，100 kHz | MPU6050 或 ICM42688 |
| EEPROM | PA4/PA5 软件 I2C（当前） | AT24C02 参数持久化 |
| 备用硬件 I2C | I2C2，PF0/PF1，100 kHz | EEPROM 硬件模式或扩展 |
| 串口 | USART1 PA9/PA10；USART2 PA2/PA3；USART3 PB10/PB11；UART4 PC10/PC11 | 调试、外设和串口屏；均 115200 |
| 电机 PWM | TIM4 CH3 PD14、CH4 PD15 | 两路直流电机 PWM |
| 电机编码器 | TIM2 PA0/PA1；TIM3 PA6/PA7 | 两路正交编码器 |
| 步进电机 | TIM9 CH1 PE5；TIM12 CH1 PB14 | 脉冲输出；另有使能/方向 GPIO |
| 系统节拍 | TIM6 1 ms；TIM10 10 ms；TIM7 20 ms | 按键/LED、快速控制预留、IMU/模式 Tick |
| OLED | PB8/PB9 软件时序 | 本地显示与参数编辑 |

## 9. 构建、烧录与再生成

### Keil 构建

1. 用 Keil MDK-ARM 打开 `Template_F407ZGT6/MDK-ARM/Template.uvprojx`。
2. 选择目标 `Template` 并 Build；工程已配置生成 HEX，输出目录为 `MDK-ARM/Template/`。
3. 工程包含 `USE_HAL_DRIVER`、`STM32F407xx` 宏和所有自定义源码目录的 Include Path。
4. 烧录/调试器配置取决于本机 Keil 和硬件连接，仓库没有命令行构建脚本或 CI。

### CubeMX 再生成

1. 打开 `Template_F407ZGT6/Template.ioc` 修改时钟、引脚或外设。
2. 保持“Keep User Code”并生成代码。
3. 生成后检查 `Core/` 的 diff，特别是 `main.c` 中的 `Mymain()` 调用和中断文件末尾的 TIM9/TIM12 自定义 IRQHandler。
4. 再检查 Keil 工程是否仍收录全部自定义 `.c` 文件；CubeMX 不一定自动管理自定义分组。

## 10. 当前风险与接手注意事项

1. **没有自动化测试和 CI。** 修改算法、协议或状态机后至少应完成编译、静态检查和板上回归；不能把“编译通过”等同于硬件行为正确。
2. **中断与前台共享状态。** `curr_mode`、串口缓冲区、EC11 计数及 IMU 数据跨上下文使用；新增共享变量时应考虑 `volatile`、原子性或临界区，避免读到半更新数据。
3. **中断内不能阻塞。** `Serial_printf()`、`HAL_Delay()`、OLED 全屏刷新和 AT24C02 单字节写入都不应加入 1/10/20 ms 回调。
4. **EEPROM 布局依赖注册顺序。** 改 `s_AT_Params[]` 前先设计兼容或擦除策略；写入一个 4 字节参数目前会触发四次单字节写周期，耗时明显。
5. **模式值会持久化。** 重排枚举会改变已保存数字的含义；新增模式应追加在 `Mode_End` 前，不要插入到已有编号中间。
6. **定时器时钟域不同。** TIM9 使用 168 MHz，TIM12 使用 84 MHz；动态调速不能假设两路同一时钟。`MyPWM` 实例中已显式保存 `Tim_Clock`。
7. **IMU 只能二选一。** MPU6050 与 ICM42688 地址相同；切宏前需确认实际焊接器件及零偏参数，不能同时挂载并直接寻址。
8. **配置与注释存在历史痕迹。** 例如模式注释仍提到电机 PID，而实际 Mode 1 已是通用离线调参；做需求判断时以调用链和当前实现为准。
9. **部分错误策略是永久卡死。** HAL 初始化失败、PWM ARR 非法、参数注册超限等会进入死循环，适合早期调试但缺少现场错误上报。
10. **第三方库体量远大于业务代码。** 搜索和代码审查默认排除 `Drivers/` 与构建输出，只有在处理底层兼容性时再进入这些目录。
11. **Emm_V5 当前存在集成风险。** 其所有命令直接使用 USART1 TX DMA，但不检查 `HAL_BUSY`；MMCL 缓冲区无越界检查，且开环电流接口在头文件与源文件中的 `ma/mA` 大小写不一致。修复前应避免连续发送和调用该名称不一致的接口。

## 11. 后续 Agent 推荐阅读顺序

针对大多数功能修改，按下面顺序能最快定位：

1. 本文与根目录 `引脚分配表.md`：先确认系统边界和接线。
2. `Template_F407ZGT6/Top/Mymain.c`：理解前台总循环和模式切换。
3. `Template_F407ZGT6/Mode/Mode_G.c`：理解初始化、系统节拍和模式分发。
4. 目标 `Mode_N.c`：确定业务逻辑实际落点。
5. `Template_F407ZGT6/Top/AllHeader.c` 与 `MySystem/MySystem.c`：确认初始化顺序和硬件实例绑定。
6. 目标功能所在的 `Hardware/`、`IMU/`、`AT/` 或 `Software/` 模块。
7. `Template.ioc`、`Core/Src/*.c`、`Core/Inc/main.h`：核对 CubeMX 的真实外设配置。
8. `MDK-ARM/Template.uvprojx`：核对源文件是否加入构建、头文件路径和编译选项。

开始改动前建议回答四个问题：功能运行在前台还是哪个 Tick；依赖哪一组引脚/定时器/DMA；状态是否跨中断共享；参数或模式是否需要断电保存。这样可以避免本工程里最常见的调度、资源冲突和 EEPROM 兼容问题。
