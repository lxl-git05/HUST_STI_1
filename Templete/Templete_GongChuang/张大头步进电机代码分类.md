# 张大头 Emm_V5 闭环步进电机代码分类

> 适用代码：`Template_F407ZGT6/Hardware/Emm_V5.c`、`Emm_V5.h`（2026-09-19 当前版本）  
> 硬性约束：**本工程后续所有张大头步进电机测试程序，只能写在 `Template_F407ZGT6/Mode/Mode_2.c`（必要声明放 `Mode_2.h`）；禁止把测试调用散落到 `main.c`、`Mode_G.c`、驱动文件或其他 Mode。**

## 1. 快速结论

这套代码是张大头 Emm_V5.0 串口协议的“命令打包与发送层”，面向 X42/Y42 系列闭环步进电机。驱动不直接产生 STEP/DIR 脉冲，而是通过 **USART1 + DMA** 向电机驱动器发送二进制命令帧。

代码有两条清晰的使用路径：

1. **单电机/直接命令：**调用 `Emm_V5_*()` 后立即执行 `HAL_UART_Transmit_DMA()`，一次发送一条协议帧。
2. **多电机/聚合命令：**调用 `Emm_V5_MMCL_*()` 或 `X_V2_MMCL_*()` 只会把子命令依次装入全局缓存；最后必须调用 `Emm_V5_Multi_Motor_Cmd()`，才会把整个缓存封装为 `0xAA` 聚合帧并发送。

当前源文件共 1733 行，头文件 235 行；公开函数共 68 个，其中：

- 单电机直接命令：47 个。
- 多电机聚合发送器：1 个，即 `Emm_V5_Multi_Motor_Cmd()`。
- 多电机 MMCL 子命令装载函数：20 个。

所有帧都以电机地址开头、以固定字节 `0x6B` 结尾。多字节数值采用高字节在前的顺序写入命令帧。

## 2. 接入位置与依赖

```text
Mode_2 测试代码
  → Emm_V5.h 公共 API
    → Emm_V5.c 组装协议帧
      → HAL_UART_Transmit_DMA(&huart1, ...)
        → USART1：PA9(TX) / PA10(RX)，115200 8N1
          → 张大头 X42/Y42 电机驱动器
```

- `Emm_V5.c` 已加入 Keil 工程的 `Hardware` 分组，因此会参与编译。
- `Emm_V5.h` 当前没有加入 `AllHeader.h`。在 Mode 2 测试时，需要在 `Mode_2.c` 中直接 `#include "Emm_V5.h"`，或以后将其统一加入聚合头；不要为了测试去改 `main.c`。
- USART1 同时被现有 `Serial1` 封装使用。当前 `Mode_2_Tick()` 每 20 ms 执行一次 `Serial_printf(&Serial1, ...)`，会和电机命令争用同一个 USART1 TX DMA。编写电机测试前应只在 Mode 2 内停用/替换这条周期打印。
- 驱动只负责发命令，没有实现电机回包解析、应答确认、超时重试或状态缓存。收到的数据仍进入工程通用的 USART1 DMA 接收链路，需要另行定义解析策略。

## 3. 第一维分类：单电机与多电机

### 3.1 单电机直接命令

命名规则：`Emm_V5_*` 或少数兼容命名 `X_V2_*`。

特点：

- 每次调用立即尝试启动 USART1 DMA 发送。
- `addr` 指定目标电机地址；代码注释指出地址 0 可作为广播地址，但实际行为仍应以对应型号手册和实机为准。
- 适合单条命令、单电机调试、读取状态以及修改驱动参数。
- 相邻两次调用不能假设都会成功：代码没有检查 `HAL_UART_Transmit_DMA()` 的返回值，USART1 忙时后一条命令可能被拒绝。

### 3.2 多电机 MMCL 命令

命名规则：`Emm_V5_MMCL_*` 或 `X_V2_MMCL_*`。

特点：

- 子命令调用时不发送，只追加到 `MMCL_cmd[512]`，并递增 `MMCL_count`。
- 最后调用 `Emm_V5_Multi_Motor_Cmd(addr)`，生成如下聚合帧：

```text
[外层地址] [0xAA] [总长度高字节] [总长度低字节]
[子命令1完整帧] [子命令2完整帧] ...
[0x6B]
```

- 聚合发送完成后，`MMCL_count` 被清零。
- 这是 Y42 新增能力；头文件明确说明 X42 不支持带 Y42 标记的命令。
- MMCL 只覆盖部分指令类型，不是所有单电机 API 都有多电机版本。

### 3.3 多电机的两种“同步”概念

代码中容易混淆的地方有两个：

- `snF`：写入某条运动命令内部的同步标志。设为 `true` 后，该命令通常进入等待同步触发的状态。
- `Emm_V5_Synchronous_motion()` / `Emm_V5_MMCL_Synchronous_motion()`：发送同步开始动作的命令。

而 `MMCL` 是“把多条协议命令装入一个大包”的传输机制。MMCL 聚合与 `snF` 同步启动解决的是不同层面的问题：前者减少/组织报文，后者控制多台电机何时真正开始动作。

## 4. 第二维分类：按指令类型

### 4.1 触发动作命令

| 功能 | 单电机 API | 多电机 MMCL API | 适用型号/备注 |
|---|---|---|---|
| 编码器校准 | `Emm_V5_Trig_Encoder_Cal` | `Emm_V5_MMCL_Trig_Encoder_Cal` | 通用 |
| 重启电机 | `Emm_V5_Reset_Motor` | `Emm_V5_MMCL_Reset_Motor` | Y42 |
| 当前位置清零 | `Emm_V5_Reset_CurPos_To_Zero` | `Emm_V5_MMCL_Reset_CurPos_To_Zero` | 通用 |
| 解除堵转保护 | `Emm_V5_Reset_Clog_Pro` | `Emm_V5_MMCL_Reset_Clog_Pro` | 通用 |
| 恢复出厂设置 | `Emm_V5_Restore_Motor` | `Emm_V5_MMCL_Restore_Motor` | 高风险，会改变驱动器配置 |

这类命令主要改变电机驱动器内部状态，不是连续运动指令。测试恢复出厂、校准、重启时必须做一次触发保护，不能把调用直接放进无条件循环或周期 Tick。

### 4.2 运动控制命令

| 功能 | 单电机 API | 多电机 MMCL API | 关键参数 |
|---|---|---|---|
| 使能/失能 | `Emm_V5_En_Control` | `Emm_V5_MMCL_En_Control` | `state`、`snF` |
| 速度模式 | `Emm_V5_Vel_Control` | `Emm_V5_MMCL_Vel_Control` | `dir`、`vel` 0～5000 RPM、`acc` 0～255、`snF` |
| 位置模式 | `Emm_V5_Pos_Control` | `Emm_V5_MMCL_Pos_Control` | 方向、速度、加速度、32 位脉冲数、`raF`、`snF` |
| 设置快速位置参数 | `Emm_V5_Set_QPos_Params` | `Emm_V5_MMCL_Set_QPos_Params` | 速度、加速度、位置模式、同步标志 |
| 快速位置运动 | `Emm_V5_QPos_Control` | `Emm_V5_MMCL_QPos_Control` | 有符号 32 位脉冲数，正负值表示方向 |
| 立即停止 | `Emm_V5_Stop_Now` | `Emm_V5_MMCL_Stop_Now` | `snF` |
| 同步开始运动 | `Emm_V5_Synchronous_motion` | `Emm_V5_MMCL_Synchronous_motion` | 通常在已下发同步等待命令后触发 |

`raF` 的代码注释定义为：0 表示相对上一输入目标位置，1 表示绝对位置，2 表示相对当前实时位置。快速位置模式把速度/加速度等参数与位移命令拆成两步，适合多次复用同一组运动参数。

### 4.3 原点回零命令

| 功能 | 单电机 API | 多电机 MMCL API | 备注 |
|---|---|---|---|
| 设置单圈零点 | `Emm_V5_Origin_Set_O` | `Emm_V5_MMCL_Origin_Set_O` | `svF` 决定是否保存 |
| 触发回零 | `Emm_V5_Origin_Trigger_Return` | `Emm_V5_MMCL_Origin_Trigger_Return` | `o_mode` 选择 4 种回零模式 |
| 中断回零 | `Emm_V5_Origin_Interrupt` | `Emm_V5_MMCL_Origin_Interrupt` | 强制退出当前回零 |
| 读取回零参数 | `Emm_V5_Origin_Read_Params` | **无** | 多电机版本未实现 |
| 修改回零参数 | `Emm_V5_Origin_Modify_Params` | `Emm_V5_MMCL_Origin_Modify_Params` | 含方向、速度、超时、碰撞阈值等 |
| 读取碰撞回零返回角度 | `X_V2_Origin_Read_SL_RP` | `X_V2_MMCL_Origin_Read_SL_RP` | X42S/Y42 |

`o_mode` 定义：0 单圈就近回零，1 单圈方向回零，2 多圈无限位碰撞回零，3 多圈有限位开关回零。修改回零参数的帧长达到 20 字节，是当前最长的常规单条命令之一。

## 6. Mode 2 测试程序放置规则

后续 Agent 编写本驱动测试时必须遵守以下规则：

1. **唯一测试入口是 `Mode_2.c`。**测试所需的静态状态、按键触发、命令调用、OLED 提示和临时串口观察逻辑都写在 Mode 2；需要对外声明时才修改 `Mode_2.h`。
2. **不得修改 `Mode_G.c` 或 `main.c` 来触发电机。**全局层只负责调度，避免一次测试污染整个工程启动流程或其他业务模式。
3. **一次性动作放在 `Mode_2_Setup()` 或带边沿/按键保护的 `Mode_2_Loop()`。**校准、恢复出厂、修改 ID、位置清零、回零等命令严禁在每轮 Loop 或周期 Tick 中无条件重复发送。
4. **周期读取可放 `Mode_2_Tick()`，但必须限频且确认 DMA 空闲。**当前 Tick 为 20 ms；不要每 20 ms 连发大包，更不要保留现有 USART1 IMU 打印与电机 DMA 命令同时争用。
5. **退出时在 `Mode_2_Exit()` 做安全收尾。**根据测试需要发送停止、失能或清除本地状态，避免切换模式后电机继续运行。
6. **先单电机、再多电机。**先验证使能、低速、短距离、停止与状态读取，再验证 `snF` 和 MMCL 聚合；首次测试应让机构悬空或留出安全行程。

推荐的职责分配：

| Mode 2 函数 | 推荐内容 |
|---|---|
| `Mode_2_Setup()` | 初始化测试状态、必要的一次性读取；不要上电即执行危险位移 |
| `Mode_2_Loop()` | 按键/命令触发单次测试步骤、OLED 状态展示、非阻塞测试状态机 |
| `Mode_2_Tick()` | 低频状态轮询或测试计时；避免连续 DMA 发送 |
| `Mode_2_Exit()` | 停止/失能、安全复位测试状态 |

## 7. 当前代码风险与问题清单

### P0：头文件与实现的函数名大小写不一致

- 头文件：`Emm_V5_Modify_OM_ma`
- 源文件：`Emm_V5_Modify_OM_mA`

C 标识符区分大小写。按头文件名称调用会在链接阶段找不到实现；在修复前不要使用该接口。修复时应统一一个名称，并同步所有调用点。

### P0：USART1 TX DMA 争用与命令丢失风险

所有发送函数都忽略 `HAL_UART_Transmit_DMA()` 的返回值。若 DMA 尚未完成就调用下一条直接命令，HAL 可能返回 `HAL_BUSY`，后一条命令不会排队。现有 `Serial_printf(&Serial1, ...)` 也使用同一 TX DMA，因此 Mode 2 测试必须先消除这一路并发发送。

### P1：MMCL 缓存没有边界检查

`MMCL_cmd` 长度固定为 512，但各 `MMCL` 函数追加数据前不检查剩余容量。装入过多子命令会越界写内存。测试代码应控制总子命令长度小于等于 512 字节；更稳妥的后续改进是集中封装带容量检查的 append 函数。

### P1：发送缓冲区生命周期与并发不受控

单电机函数多使用函数内 `static` 缓冲区，MMCL 使用全局缓存。它们不是可重入设计；中断和前台同时调用、或同一函数在 DMA 未完成时再次调用，都可能修改正在发送的数据。

### P1：没有回包解析和事务状态机

读取类函数的返回值是 `void`，代码无法知道驱动器是否响应、响应内容是否匹配请求，也没有超时/重试。测试输出不能仅凭“发送函数被调用”判断成功，必须观察并解析实际回包或电机行为。

### P2：参数范围只写在注释里

例如速度、加速度、模式值和 ID 没有运行时校验。越界值会原样进入协议帧，结果取决于驱动器固件。Mode 2 测试应使用明确的安全范围，不能依赖底层自动限幅。

### P2：无效 `SysParams_t` 会形成短帧

两个系统参数函数的 `switch` 对无效枚举只执行 `default: break`，仍会继续补尾字节并发送。调用方必须只传头文件定义的 18 个枚举值。

### P2：源码末尾显示多电机能力尚未继续扩展

`Emm_V5.c` 最后停在“读写驱动参数命令”标题，没有对应 MMCL 实现。这与头文件一致，说明当前不是漏声明，而是多电机驱动参数配置功能尚未提供。

## 8. 后续 Agent 的最短接手路径

1. 阅读 `Emm_V5.h` 获取可用 API 和型号限制。
2. 阅读本文第 4、5 节确认单/多电机能力与指令类别。
3. 核对 USART1 物理连线、电机地址、波特率和共地。
4. 只在 `Mode_2.c` 编写测试状态机；先移除/停用现有 USART1 IMU 周期打印。
5. 首先测试低风险读取命令，再测试使能、低速运动、短距离位置运动和停止。
6. 多电机测试时先清晰计算 MMCL 总长度，依次装载子命令，最后仅调用一次 `Emm_V5_Multi_Motor_Cmd()`。
7. 不把驱动器无应答、DMA 启动成功和电机动作成功混为一谈；三者需要分别验证。
