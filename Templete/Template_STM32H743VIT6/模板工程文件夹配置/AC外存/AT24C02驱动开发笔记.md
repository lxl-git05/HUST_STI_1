# AT24C02 驱动开发完整笔记

> 本项目基于 STM32F103C8Tx + HAL 库，完整实现 AT24C02 EEPROM 的硬件I2C/软件I2C 双模式驱动，并构建了参数管理层。

---

## 一、文件架构

```
Hardware/
├── bsp_at24c02.c/.h       # 底层驱动（硬件I2C or 软件I2C）
├── at24c02_manager.c/.h   # 参数管理层（自动地址分配，读写抽象）
└── Param_AT24C02.c/.h    # 业务层（用户全局变量统一注册点）

Top/
└── Mymain.c               # 业务入口，测试代码
```

## 二、驱动分层

### 第1层：bsp_at24c02（底层）

负责最原始的 I2C 通信，**两种模式通过一个宏切换**：

```c
// bsp_at24c02.h 第10行
#define AT24C02_USE_SW_I2C    1   // 1=软件I2C，0=硬件I2C
```

| 模式 | 宏=1（软件I2C） | 宏=0（硬件I2C） |
|------|----------------|---------------|
| 引脚 | PB14(SCL) / PB15(SDA) | PB10(SCL) / PB11(SDA) |
| 实现 | GPIO bit-bang 时序模拟 | HAL_I2C_Mem_Write/Read |
| 初始化 | `AT24C02_Init()` 拉高SCL/SDA | 空（MX_I2C2_Init已初始化） |

**切换方法**：改一行宏，重新编译即可。

### 第2层：at24c02_manager（参数管理层）

- **自动地址分配**：用户只填变量指针和默认值，地址由系统顺序分配，从0开始
- **类型自动识别**：`AT_PARAM_I8 / I16 / I32 / F` 宏按类型分开注册
- **读写接口**：全部用**变量指针**作为 Key，不暴露地址给用户
- **溢出检测**：参数表最大30项，超限 `while(1)` 死锁报警

### 第3层：Param_AT24C02（业务层）

用户所有需要掉电保存的全局变量，**统一在此文件中定义和注册**。其他模块 `extern` 声明后直接使用。

## 三、核心 API

### bsp_at24c02（底层）

| 函数 | 说明 |
|------|------|
| `AT24C02_Init()` | 初始化（软件I2C拉高总线，硬件I2C空操作） |
| `AT24C02_WriteByte(addr, data)` | 写1字节，返回1=成功 |
| `AT24C02_ReadByte(addr)` | 读1字节，返回读到的值 |

### at24c02_manager（管理层）

| 函数 | 说明 |
|------|------|
| `AT_Manager_Register(item)` | 注册一个参数项（自动分配地址） |
| `AT_Manager_Init()` | 上电调用：遍历已注册项，读AT恢复，失败用默认值 |
| `AT_Manager_Write(varPtr)` | 将变量的当前值写入AT，返回1=成功 |
| `AT_Manager_Read(varPtr)` | 从AT读取值写入变量，返回1=成功 |
| `AT_Manager_SaveAll()` | 批量写入所有参数 |
| `AT_Manager_LoadAll()` | 批量从AT读取所有参数 |
| `AT_Manager_GetATAddr(varPtr)` | 通过变量指针反查AT地址（调试用） |
| `AT_Manager_GetCount()` | 获取已注册参数数量 |

### Param_AT24C02（业务层）

| 函数 | 说明 |
|------|------|
| `Param_AT24C02_Init()` | 注册所有参数 + 上电恢复 |
| `Param_AT24C02_EraseAll()` | 擦除整个AT24C02（填0xFF） |
| `Param_AT24C02_SaveAll()` | 批量保存所有参数 |
| `Param_AT24C02_Write(varPtr)` | 保存单个变量到AT |
| `Param_AT24C02_Read(varPtr)` | 从AT读取单个变量 |

## 四、注册宏详解

### 为什么不用 _Generic？

计划阶段尝试用 `_Generic`（C11）让编译器根据变量类型**自动识别 INT32 还是 FLOAT**，但：
- **ARMCC（Keil）不支持 `_Generic`**（属于 GCC 扩展）
- 所以改用**显式分宏**：`AT_PARAM_I8` / `AT_PARAM_I16` / `AT_PARAM_I32` / `AT_PARAM_F`

### 四个注册宏

```c
// int8_t 类型
{ AT_PARAM_I8(&g_mode, 0) }        // size=1, type=INT8

// int16_t 类型
{ AT_PARAM_I16(&g_value, 100) }    // size=2, type=INT16

// int32_t 类型
{ AT_PARAM_I32(&g_count, 0) }      // size=4, type=INT32

// float 类型
{ AT_PARAM_F(&g_kp, 1.0f) }        // size=4, type=FLOAT
```

### 为什么 INT32 和 FLOAT 都有4字节，却不会冲突？

```c
typedef enum {
    AT_TYPE_INVALID = 0,
    AT_TYPE_INT8    = 1,
    AT_TYPE_INT16   = 2,
    AT_TYPE_INT32   = 3,   // 3≠4，不重复
    AT_TYPE_FLOAT   = 4
} AT_ParamType;
```

枚举值**唯一**，所以 switch 中 `case AT_TYPE_INT32` 和 `case AT_TYPE_FLOAT` 不会冲突。

### 为什么不用 C99 指定初始化器 `{ .field = value }`？

ARMCC **不完全支持** C99 指定初始化器，报错 `a designator cannot be used with a non-aggregate type`。所以：
- 结构体字段顺序与宏展开顺序**一一对应**
- 宏按顺序展开：`type, size, varPtr, {defVal}, 0(atAddr占位)`

## 五、地址自动分配原理

```c
static uint8_t s_nextAddr = 0;   // 下一个待分配地址

static uint8_t AllocAddr(uint8_t size)
{
    uint8_t addr = s_nextAddr;
    s_nextAddr += size;           // 顺序递增，不重叠
    return addr;
}
```

以本项目的参数表为例：

| 变量 | 类型 | 大小 | AT地址 |
|------|------|------|--------|
| `g_mode` | int8_t | 1 | 0 |
| `g_motorSpeed` | int32_t | 4 | 1 |
| `g_pidKp` | float | 4 | 5 |
| `g_pidKi` | float | 4 | 9 |
| `g_pidKd` | float | 4 | 13 |

**重点**：`g_motorSpeed` 占地址1-4，`g_pidKp` 从地址5开始，**恰好错开**。

## 六、掉电恢复流程

```
上电
  │
  ▼
Param_AT24C02_Init()
  │
  ▼
for 遍历每个已注册参数
  │
  ├── AT24C02_ReadByte(addr) → 读AT
  │
  ├── 判断：读到0xFF？→ 视为空/未存储
  │         用默认值初始化变量
  │
  └── 否则：用AT的值覆盖变量
```

**注意**：AT24C02 出厂默认全 0xFF，所以**未写入过的地址读出来就是 0xFF**，正好作为空值判断依据。

---

## 七、多字节数据的存储顺序

`INT16 / INT32 / FLOAT` 均为**小端存储**（低字节在前）：

```c
// 以 INT32 值 0x12345678 存储在地址 a 为例：
AT[a+0] = 0x78  // 低字节
AT[a+1] = 0x56
AT[a+2] = 0x34
AT[a+3] = 0x78  // 高字节
```

`float` 按**IEEE 754 字节流**存储，读写时直接 `memcpy` 内存表示，不做任何转换。

## 八、使用方法（业务层）

### 1. 添加/修改全局变量

在 `Param_AT24C02.c` 中：

```c
// ---------- 业务全局变量 ----------
extern int32_t  g_motorSpeed;   // ← 去掉 extern 就是定义
extern float    g_pidKp;
extern int8_t   g_mode;
// ... 按业务添加
```

### 2. 在参数表中注册

```c
static const AT_ParamItem s_AT_Params[] = {
    { AT_PARAM_I8(&g_mode, 0)         },   // 首位，地址=0
    { AT_PARAM_I32(&g_motorSpeed, 0)  },   // 地址顺序分配
    { AT_PARAM_F(&g_pidKp, 1.0f)      },
    // ... 更多参数
};
```

**重点**：`g_mode` 放在第一个，后续地址分配从这里开始。

### 3. 初始化（整个系统只调一次）

```c
// Mymain.c 或 Initial.c 中
Param_AT24C02_Init();   // 注册 + 上电恢复
```

### 4. 运行时读写

```c
// 修改变量后保存
g_pidKp = 2.5f;
Param_AT24C02_Write(&g_pidKp);   // 单个保存

// 或批量保存
Param_AT24C02_SaveAll();          // 所有参数写入AT

// 从AT重新读取（覆盖本地变量）
Param_AT24C02_Read(&g_pidKp);    // 单个读取
Param_AT24C02_LoadAll();          // 批量读取

// 擦除整个AT（恢复出厂状态）
Param_AT24C02_EraseAll();         // 填0xFF
```

### 5. 其他模块使用变量

```c
// 例如在 Control/Task.c 中
#include "Param_AT24C02.h"

void Task_MotorControl(void)
{
    int32_t speed = g_motorSpeed;   // 直接使用
    g_pidKp = 3.0f;                 // 直接修改
}
```

## 九、重点和注意点

### 1. 模式切换只需改一个宏

```c
// bsp_at24c02.h
#define AT24C02_USE_SW_I2C    1   // 1→软件I2C，0→硬件I2C
```

### 2. g_mode 必须放第一位

因为参数表按顺序自动分配地址，`g_mode` 放第一位的目的是保证**地址0**永远是模式参数，便于后续业务逻辑扩展。

### 3. 地址分配是纯顺序的，与类型无关

注册时按宏展开顺序**连续分配**，下一个参数的起始地址 = 上一个参数的起始地址 + size。**不需要看顺序，也不需要手动对齐**，系统自动处理。

示例：本项目 `g_mode`(1B)→`g_motorSpeed`(4B)→`g_pidKp`(4B)→`g_pidKi`(4B)→`g_pidKd`(4B)，地址依次为 0→1→5→9→13，全自动，无需干预。

### 4. float 和 int32 不能共用参数项

虽然都是4字节，但存储和解析方式完全不同：
- `AT_PARAM_I32` → 读写按 int32 小端
- `AT_PARAM_F` → 读写按 float IEEE 754 位模式

### 5. 擦除后必须重新 Init

```c
Param_AT24C02_EraseAll();   // 填0xFF
Param_AT24C02_Init();        // 再次注册+恢复，此时全部判定为空→用默认值
```

### 6. AT24C02 写入需要5ms等待

`AT24C02_WriteByte` 内部有 `HAL_Delay(5)`，批量写入时耗时长（256字节≈1.3秒）。`SaveAll` 只保存已注册参数，速度快得多。

### 7. AT 地址有效范围是 0~255

AT24C02 只有 256 字节（2Kb），如果参数总大小超过 256 字节，需要自行规划跨页存储或分块。

### 8. ARMCC 编译器限制

- 不支持 `_Generic`（C11）
- 不完全支持 C99 指定初始化器 `.field = value`
- 结构体字段顺序必须与初始化器顺序完全一致

## 十、驱动原理（软件I2C时序）

### I2C 起始信号
```
SCL=1 期间，SDA 由 H→L 跳变
```
### I2C 停止信号
```
SCL=1 期间，SDA 由 L→H 跳变
```
### 字节传输（MSB先发）
```
SCL低 → SDA放置bit → SCL高(采样) → SCL低 → 下一bit
```
### 应答检测
```
第9个时钟周期，从机拉低SDA表示应答
```
### AT24C02 单字节写时序
```
Start → 设备写地址(0xA0) → ACK → 字地址 → ACK → 数据 → ACK → Stop → 等待5ms内部写周期
```
### AT24C02 单字节读时序
```
Start → 设备写地址(0xA0) → ACK → 字地址 → ACK
→ Start(重复起始) → 设备读地址(0xA1) → ACK → 读数据 → NACK → Stop
```

## 十一、常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 读回来的值全是0xFF | AT未写入过，或写入后断电未保存 | 调用SaveAll保存 |
| 写成功但读回来不对 | 多字节数据类型用了错误的宏 | float用AT_PARAM_F |
| 编译报错 case重复 | INT32和FLOAT枚举值相同 | 本项目已改为3和4 |
| 上电后变量是默认值不是AT存的 | EraseAll后没有重新Init | EraseAll后调用Init |
| LED快闪但值没变 | Write失败（I2C不通） | 检查硬件接线，PB14/PB15或PB10/PB11 |
